## System components

**1. Job input and data fetching**
- Input: an area (drawn box or polygon) plus a flood date.
- Scene finder: picks Sentinel-1 before/after images on the same track, plus the clearest Sentinel-2 before/after pair.
- Fetchers for the Copernicus DEM and for OSM via ohsome, pinned to the 2026-07-27 snapshot.
- An allowlist so nothing outside the allowed inputs can be loaded. This protects you from disqualification.

**3. Flood and debris mapping** (30% of the score)
- Classical radar change detection: log-ratio plus automatic thresholding.
- The ML model.
- A debris/scour change detector, because debris doesn't look like water on radar.
- Sentinel-2 indices (water, vegetation loss, bare soil) whenever the sky is clear.
- A fusion step that combines these, applies the HAND/physics constraints, and outputs a confidence level and a "not observable" mask.

**4. AI component** (25%)
- If you choose option (a), segmentation: a training pipeline (for example UNet-ResNet50 on Kuro Siwo), saved weights, and an evaluation on held-out mountain events plus zero-shot on Rasuwa.
- If you choose option (b), the copilot: Q&A plus sitreps in English and Nepali, with a checker that confirms every number in the text against the system's own database.

**5. Damage overlay**
- Pre-event OSM buildings, roads and bridges intersected with the flood/debris map.
- A separate check for each bridge, since bridges drive the cut-off analysis.

**6. Cut-off analysis** (20%)
- A road and trail graph built from OSM.
- Damaged edges and bridges removed.
- A reachability test from each settlement to the nearest hospital and town.
- Output: each settlement's status, plus a ranking of which bridge repairs would reconnect the most people.

**7. Bonus: flow-path tracing.** Click an upstream point, trace the flow down the valley on the DEM, and list the settlements along the path in order.

**8. Situation report generator.** A one-page PDF or HTML report where every figure comes from your results database. The Nepali version is required only for option (b); otherwise it's a bonus.

**9. Dashboard** (10%)
- Area selection and date picker, a run button, and progress status.
- Layer toggles: flood, debris, damaged items, cut-off settlements, flow path.
- A settlement list.
- Downloads: GeoJSON and the sitrep.

**10. Backend and infrastructure**
- An API with a job queue, result storage, and caching.
- Docker Compose for reproducible runs.
- A hosted instance. Judges test live on areas and dates they choose, so the pipeline must run on new inputs in minutes.

**11. Validation**
- A separate notebook comparing your output with EMSR927. Use it only for checking; it must never feed the pipeline.
- Metrics: IoU, precision and recall, and building-level hit rates.
- Failure cases go into the report.
